Lista wspiera kwalifikowanie i wyszukiwanie zasobów, sprawdzanie kompletności inwentaryzacji oraz rozpoznawanie zdarzeń wymagających aktualizacji rejestru. Nie służy do oceny zgodności zasobów z WCAG.

## 1. Czym jest zasób cyfrowy organizacji

Zasób cyfrowy to rozwiązanie cyfrowe, za którego utworzenie, zakup, utrzymanie, rozwój, publikację lub udostępnianie organizacja odpowiada w całości albo w części i którym może w określonym zakresie zarządzać.

**Inwentaryzacja nie jest listą stron internetowych, aplikacji i systemów, z których korzystają pracownicy. Obejmuje zasoby, za które organizacja odpowiada albo na które ma realny wpływ.**

Samo korzystanie z zewnętrznej strony, aplikacji albo usługi nie oznacza, że jest ona zasobem organizacji. Znaczenie ma rzeczywisty zakres odpowiedzialności i wpływu organizacji, a nie tylko dostęp pracowników do rozwiązania.

## 2. Test: czy to jest zasób organizacji

Rozwiązanie analizuje się pod kątem ujęcia w inwentaryzacji, jeżeli odpowiedź na co najmniej jedno z poniższych pytań brzmi „tak”:

| Pytanie | Tak | Nie | Uwagi |
| --- | --- | --- | --- |
| Czy organizacja utworzyła rozwiązanie albo zleciła jego utworzenie? | ☐ | ☐ | |
| Czy organizacja kupiła, finansuje albo utrzymuje rozwiązanie? | ☐ | ☐ | |
| Czy organizacja może zmieniać jego konfigurację, treść lub funkcje? | ☐ | ☐ | |
| Czy organizacja publikuje za jego pomocą własne treści albo świadczy usługę? | ☐ | ☐ | |
| Czy organizacja odpowiada za jego dostępność albo może wymagać jej od wykonawcy? | ☐ | ☐ | |
| Czy rozwiązanie jest elementem większego zasobu organizacji? | ☐ | ☐ | |

Test jest narzędziem organizacyjnym wspierającym kwalifikację. Nie stanowi kryterium prawnego i nie zastępuje ustalenia obowiązków dotyczących konkretnego zasobu.

Spełnienie jednego z warunków oznacza potrzebę przeanalizowania rozwiązania, a nie automatycznie obowiązek ujęcia go jako samodzielnego zasobu w rejestrze.

## 3. Przykłady: tak, nie, sprawdź

| Przykład | Czy inwentaryzować? | Dlaczego |
| --- | --- | --- |
| Główna strona internetowa organizacji | Tak | Organizacja odpowiada za jej publikację, treść i utrzymanie albo zleca te działania. |
| Biuletyn Informacji Publicznej organizacji | Tak | Organizacja publikuje w nim własne informacje i odpowiada za ich udostępnianie. |
| Aplikacja mobilna zamówiona przez organizację | Tak | Organizacja zleciła jej utworzenie i może określać wymagania wobec wykonawcy. |
| Aplikacja webowa utrzymywana przez wykonawcę | Tak | Zewnętrzne utrzymanie nie znosi odpowiedzialności organizacji za własne rozwiązanie. |
| System SaaS wykorzystywany przez organizację do realizacji własnej usługi lub procesu | Tak | Organizacja wykorzystuje rozwiązanie do realizacji własnych zadań i ma wpływ na warunki jego używania. |
| E-usługa organizacji | Tak | Organizacja świadczy za jej pomocą usługę użytkownikom. |
| Formularz elektroniczny jako element serwisu | Tak | Jest elementem zasobu nadrzędnego i służy realizacji procesu organizacji. |
| Dokument PDF publikowany przez organizację | Tak, jako element zasobu nadrzędnego | Organizacja odpowiada za publikowaną treść; dokument zwykle nie wymaga odrębnego wpisu równorzędnego z serwisem. |
| Strona banku używana przez pracowników | Nie | Organizacja wyłącznie korzysta z zewnętrznej strony i nie odpowiada za nią. |
| Serwis pogodowy | Nie | Samo korzystanie z ogólnodostępnego serwisu nie tworzy odpowiedzialności za zasób. |
| Ogólnodostępna wyszukiwarka | Nie | Organizacja nie tworzy jej, nie utrzymuje i nie kontroluje. |
| Zewnętrzna strona internetowa, z której pracownicy tylko korzystają | Nie | Brakuje odpowiedzialności organizacji i realnego wpływu na rozwiązanie. |
| Zewnętrzna usługa bez odpowiedzialności ani wpływu organizacji | Nie | Sam dostęp do usługi nie czyni jej zasobem organizacji. |
| Serwis gov.pl wykorzystywany przez organizację | Sprawdź | Trzeba ustalić, czy organizacja publikuje własne treści, zarządza częścią serwisu lub odpowiada za jej dostępność. |
| ePUAP | Sprawdź | Trzeba rozdzielić odpowiedzialność za platformę centralną od odpowiedzialności organizacji za własne usługi, formularze i treści. |
| System centralny udostępniony organizacji | Sprawdź | Trzeba ustalić zakres konfiguracji, utrzymania, publikacji treści i odpowiedzialności organizacji. |
| Moduł systemu skonfigurowany specjalnie dla organizacji | Sprawdź | Trzeba ustalić, czy organizacja zarządza modułem lub może wymagać zmian od dostawcy. |
| Rozwiązanie wspólne dla kilku jednostek | Sprawdź | Trzeba ustalić podział odpowiedzialności i wpływu między jednostkami. |
| Serwis jednostki organizacyjnej | Sprawdź | Trzeba ustalić, która jednostka odpowiada za publikację, utrzymanie i dostępność serwisu. |
| Platforma utrzymywana przez podmiot nadrzędny | Sprawdź | Trzeba ustalić, czy organizacja odpowiada za własną część platformy, konfigurację, treści lub świadczone usługi. |

## 7. Kiedy zaktualizować rejestr

Rejestr aktualizuje się w szczególności, gdy:

1. powstaje nowy zasób;
2. organizacja kupuje albo wdraża nowe rozwiązanie;
3. zmienia się właściciel zasobu lub odpowiedzialność za niego;
4. zmienia się dostawca;
5. następuje istotna zmiana techniczna lub funkcjonalna;
6. przeprowadzono ocenę dostępności;
7. wykonano działania naprawcze;
8. zaktualizowano deklarację dostępności;
9. zasób został wycofany albo zastąpiony.
