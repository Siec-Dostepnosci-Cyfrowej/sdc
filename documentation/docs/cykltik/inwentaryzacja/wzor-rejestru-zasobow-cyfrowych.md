Wzór przedstawia model informacji potrzebnych do zarządzania inwentaryzacją zasobów cyfrowych. Nie narzuca konkretnego programu ani technologii.

Organizacja może dostosować zestaw i nazwy pól do swojej wielkości, struktury, narzędzi i sposobu działania. Zachowuje jednak informacje potrzebne do identyfikowania zasobów, określania odpowiedzialności i wymagań, dokumentowania stanu dostępności oraz aktualizowania danych w całym cyklu życia zasobu.

Jeżeli kilka ról pełni ta sama osoba, komórka lub zespół, organizacja może wskazać ten sam podmiot w odpowiednich polach.

## 1. Identyfikacja zasobu

| Pole | Opis |
| --- | --- |
| Identyfikator | Jednoznaczny identyfikator zasobu albo elementu zasobu. |
| Nazwa | Nazwa zasobu stosowana w organizacji. |
| Typ zasobu | Typ, na przykład strona internetowa, aplikacja mobilna, aplikacja webowa, system wewnętrzny, dokument, multimedia, formularz, mapa lub komponent. |
| Opis lub funkcja | Krótki opis przeznaczenia zasobu i jego znaczenia dla organizacji lub użytkowników. |
| URL lub inna lokalizacja | Adres URL, lokalizacja w systemie albo inne oznaczenie miejsca udostępniania. |
| Zasób nadrzędny | Identyfikator albo nazwa zasobu, którego częścią jest dany element. Pole pozostaje puste dla zasobu głównego. |
| Relacje z innymi zasobami | Powiązania istotne dla dostępności, utrzymania, realizacji usługi albo zarządzania zmianą. |
| Status cyklu życia | Status, na przykład planowany, tworzony lub nabywany, wdrażany, eksploatowany, modernizowany, wycofywany, wycofany albo archiwalny. |

## 2. Odpowiedzialność

| Pole | Opis |
| --- | --- |
| Właściciel biznesowy | Osoba, komórka albo rola odpowiadająca za funkcję zasobu i decyzje dotyczące jego utrzymania, rozwoju lub wycofania. |
| Komórka organizacyjna | Jednostka lub komórka organizacyjna odpowiedzialna za zasób. |
| Utrzymanie techniczne | Osoba, komórka, zespół albo podmiot odpowiadający za techniczne utrzymanie lub rozwój zasobu. |
| Wykonawca lub dostawca | Podmiot zewnętrzny istotny dla rozwoju, utrzymania lub napraw zasobu. |
| Odpowiedzialność za treści | Osoba, komórka albo rola odpowiadająca za treści publikowane w zasobie. |
| Odpowiedzialność za dostępność | Osoba, komórka albo rola koordynująca wymagania, oceny, ryzyka i działania dotyczące dostępności zasobu. |

## 3. Zakres wymagań

| Pole | Opis |
| --- | --- |
| Sposób udostępniania | Informacja, czy zasób jest publiczny, wewnętrzny, udostępniany wybranym grupom, czy stanowi element usługi albo procesu wewnętrznego. |
| Główni odbiorcy | Główne grupy użytkowników zasobu. |
| Podstawa kwalifikacji wymagań | Przepis, umowa, standard organizacji, decyzja wewnętrzna albo inna podstawa zastosowania wymagań. |
| Mające zastosowanie wymagania | Wymagania dostępności właściwe dla zasobu, określone zgodnie z jego typem, funkcją, sposobem udostępniania i podstawą zastosowania. |
| Wyłączenia lub ograniczenia | Uzasadnione wyłączenia, ograniczenia zakresu albo szczególne uwarunkowania, jeżeli występują. |
| Uzasadnienie kwalifikacji | Krótkie wyjaśnienie przyjętego zakresu wymagań, jeżeli jest potrzebne do odtworzenia podstaw decyzji. |

Zakres wymagań ustala się dla konkretnego zasobu. Wpis nie przypisuje automatycznie wymagań Europejskiego Aktu o Dostępności ani całej normy EN 301 549 do każdego zasobu. Poziomy A i AA odnoszą się do WCAG, a nie do EN 301 549.

## 4. Stan dostępności

| Pole | Opis |
| --- | --- |
| Znany stan dostępności | Aktualnie znany stan, z rozróżnieniem braku wiedzy, oceny częściowej i stwierdzonych problemów. |
| Źródło informacji | Źródło wiedzy, na przykład audyt, ocena ekspercka, wynik badania automatycznego, zgłoszenie użytkownika, odbiór prac albo informacja od dostawcy. |
| Rodzaj ostatniej oceny | Typ oceny, na przykład pełna, częściowa, automatyczna, ekspercka, redakcyjna, odbiorowa albo ponowna po naprawie. |
| Data oceny | Data ostatniej oceny albo innego źródła wiedzy o stanie. |
| Zakres oceny | Zakres objęty oceną, na przykład cały zasób, wybrane ekrany, próbka dokumentów, formularz, proces użytkownika albo komponent. |
| Raport lub inny dowód | Link albo oznaczenie dokumentu potwierdzającego źródło informacji. |
| Zidentyfikowane problemy | Najważniejsze znane problemy dostępności i ich wpływ na użytkowników. |

Wynik badania automatycznego opisuje się jako wynik tego badania, a nie jako procent zgodności z WCAG.

## 5. Zarządzanie

| Pole | Opis |
| --- | --- |
| Ryzyko lub znaczenie zasobu | Znaczenie zasobu i skutki jego niedostępności dla użytkowników, usług lub organizacji. |
| Planowane działania | Działania dotyczące oceny, naprawy, ograniczenia ryzyka, aktualizacji deklaracji, modernizacji albo wycofania zasobu. |
| Priorytet | Priorytet ustalony według skali przyjętej w organizacji. |
| Odpowiedzialność za działanie | Osoba, komórka, zespół albo dostawca odpowiedzialny za realizację działania. |
| Termin działania lub następnego przeglądu | Termin wykonania działania, kolejnej oceny albo przeglądu danych. |
| Data ostatniej aktualizacji wpisu | Data ostatniej merytorycznej aktualizacji danych o zasobie. |

## 6. Deklaracja dostępności, jeżeli ma zastosowanie

| Pole | Opis |
| --- | --- |
| Deklaracja wymagana | Informacja, czy dla zasobu jest wymagana deklaracja dostępności. |
| URL deklaracji | Adres opublikowanej deklaracji właściwej dla strony internetowej lub aplikacji mobilnej. |
| Data sporządzenia | Data sporządzenia deklaracji. |
| Data ostatniego przeglądu lub aktualizacji | Data ostatniego przeglądu albo aktualizacji deklaracji. |
| Status aktualności | Informacja, czy deklaracja jest aktualna, wymaga aktualizacji albo czy trwają czynności wyjaśniające. |

Informacje o deklaracji przypisuje się do właściwej strony internetowej lub aplikacji mobilnej. Pojedynczy dokument PDF, nagranie, formularz lub inny element zasobu nie otrzymuje własnej deklaracji, jeżeli jest objęty deklaracją zasobu nadrzędnego.
